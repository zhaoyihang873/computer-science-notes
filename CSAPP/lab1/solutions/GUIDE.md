# Data Lab 逐题订正

与本页配套的 [参考实现](bits.c) 覆盖自学包的 13 道题。订正时先用 `btest` 找一个失败输入，手算预期结果并对照下面相应的小节。若结果正确但规则检查失败，再用 `dlc -e` 查可用运算符和实际运算次数。

整数题按实验模型使用 32 位补码和算术右移。构建配置对有符号加减使用 `-fwrapv`，以保留补码环绕行为。浮点题处理的是 IEEE 754 binary32 的位模式，布局为 1 位符号、8 位阶码、23 位小数。以下十六进制边界用来手算和测试，整数题实现里的常量仍须在 `0x00` 到 `0xFF` 之间。

## 1. `bitXor`

1. 逐位看，异或为 1 的充要条件是两位不同。排除「都为 1」和「都为 0」即可。
2. 用 `~(x & y)` 排除都为 1，用 `~(~x & ~y)` 排除都为 0，再将两条件相与。全程只用了 `~`、`&`。

自查 `x == y` 时输出全零，`y == 0` 时输出 `x`。

## 2. `tmin`

1. 32 位补码的最高位权重为 `-2^31`，其余位的权重为正。
2. 把最低位的 1 左移 31 位，得到 `0x80000000`。

自查只有最高位是 1。

## 3. `isTmax`

1. 最大补码整数加 1 会得到最小补码整数，恰好也等于逐位取反的结果。
2. 在模 `2^32` 下，`x + 1 == ~x` 等价于 `2 * (x + 1) == 0`，所以 `x + 1` 只能是零或 `0x80000000`。
3. 用异或加逻辑非判相等，再用 `!!(x + 1)` 排除 `x == -1`。

自查 `0x7FFFFFFF`、`0x80000000` 和 `-1`。

## 4. `allOddBits`

1. 从最低位编号 0 开始，单字节的奇数位掩码是 `0xAA`。用位移和按位或将它扩成 16 位，再扩成 32 位。
2. 用 `x & mask` 取出奇数位，再与整个掩码判等。偶数位会被掩掉。

自查 `0xAAAAAAAA` 通过，`0xFFFFFFFD` 因为第 1 位为零而失败。

## 5. `negate`

1. 一个 32 位数与它的按位取反相加，所有位都为 1，也就是 `-1`。
2. 在取反结果上加 1，便得到补码意义下的相反数。

自查 `0`、`1` 和最小补码整数。最后一种的位模式在 32 位环绕下保持为 `0x80000000`。

## 6. `isAsciiDigit`

1. `0x30` 到 `0x39` 的高位右移 4 位后恰好等于 3。用异或加逻辑非检查这一条件。
2. 低四位范围是 0 到 15。给它加 6，原值为 0 到 9 时仍小于 16。结果右移 4 位后为零，说明低位在范围内。
3. 两项检查都为真时返回 1。

自查 `0x2F`、`0x30`、`0x39`、`0x3A` 和 `0x130`。

## 7. `conditional`

1. 用 `!!x` 得到 0 或 1，再通过取反加一，把它转换成全零或全一的按位掩码。
2. 掩码全一时保留 `y`，互补掩码会清零 `z`。掩码全零时反过来。将两部分按位或。

自查条件为 `0` 和负数的情况。

## 8. `isLessOrEqual`

1. 取出两个符号位。符号不同的情况下，只有 `x` 为负才满足 `x <= y`。
2. 符号相同时，两数的低 31 位保持原来的大小顺序。去掉最高位得到两个非负数，用取反加一计算低位部分的 `y - x`。这个差的范围属于 32 位有符号整数。
3. 差为非负时成立，包含两数相等。用符号是否相同来选取这两种判断的结果。

自查 `INT_MIN <= INT_MAX`、`INT_MAX <= INT_MIN`、`-2 <= -1`，以及 `INT_MIN <= INT_MIN`。

## 9. `logicalNeg`

1. `x == 0` 时，它的补码相反数也为零。
2. 非零时，`x` 和它的相反数至少有一个的符号位为 1。最小补码整数的相反数仍是自己，也符合这一性质。
3. 对二者按位或并算术右移 31 位。得到的 `0` 或 `-1` 加一后，分别对应逻辑非的 `1` 或 `0`。

自查 `0`、`1`、`-1` 和最小补码整数。

## 10. `howManyBits`

1. 负数的冗余位是开头多余的 1。用 `x ^ (x >> 31)` 让负数取反、非负数保持原值，使两种情况都归结为找最高的 1。
2. 依次查是否需要跳过 16、8、4、2、1 位。每次用 `!!` 得到 0 或 1，变成位移量后移走低位，并把位移量计入结果。
3. 最后留下的 `bits` 为 0 或 1，表示有效位是否存在。加上它和 1 位符号位得到答案。

自查 `0` 和 `-1` 都需要 1 位，`12` 需要 5 位，`-5` 需要 4 位，最小补码整数需要 32 位。

## 11. `floatScale2`

1. 取出符号、阶码和小数。阶码全一表示 NaN 或无穷大，将原位模式返回即可。
2. 阶码为零时，将小数字段左移一位，然后恢复符号。左移出来的最高小数位若进入阶码，就自然得到最小一带的规格化值。
3. 其余有限规格化值的阶码加 1。原阶码为 254 时，结果是同号无穷大，需要清空小数字段。

自查 `0x80000000` 的负零、`0x00400000` 跨入规格化区间、`0x7F7FFFFF` 溢出，以及保留 NaN 的原始位模式。

## 12. `floatFloat2Int`

1. 将阶码减去偏置 127，得到实际指数。实际指数小于 0 时，值的绝对值小于 1，按向零截断得到 0。
2. 实际指数大于 30 时，返回约定的 `0x80000000u`。这也覆盖 NaN、无穷大，以及恰好等于 `-2^31` 的情况，后者的合法整数恰好具有同样的位模式。
3. 其余输入都是规格化数。补回隐含的最高位 1，再根据指数与 23 的差向左或向右移。右移会丢掉小数位。
4. 绝对值构造完毕后再应用符号，确保像 `-1.75` 这样的值向零截断为 `-1`。

自查 `0xBFE00000`、`0x4EFFFFFF`、`0x4F000000` 和 `0xCF000000`。

## 13. `floatPower2`

1. `x > 127` 时返回正无穷大。`x < -149` 时返回正零。
2. `-126 <= x <= 127` 时是规格化值。正号、小数为零，阶码为 `x + 127`。
3. `-149 <= x < -126` 时是次正规值。小数字段最低位代表 `2^-149`，所以将 1 左移 `x + 149` 位。

自查 `-150`、`-149`、`-127`、`-126`、`127` 和 `128`。这六个输入分别覆盖两端的边界和次正规到规格化的过渡。
